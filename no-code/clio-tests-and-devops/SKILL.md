# clio: tests and DevOps

Read on clio 8.1.0.145; **not verified** on Creatio 8.2.3 except `install-gate` (the gate
was already present at 2.0.0.43). Command pages: [reference/](../reference/).

```bash
clio new-test-project ... -e dev              # NUnit project referencing the environment's core
clio new-integration-test-project ...         # ATF.Repository based integration tests
clio new-ui-project ...                       # Angular remote module scaffold
clio run <scenario.yaml>                      # scripted sequence of clio commands
clio assert ...                               # infrastructure checks
clio pack-nuget-pkg / push-nuget-pkg / restore-nuget-pkg ...
clio build-docker-image ...
clio install-gate -e dev                      # cliogate, required by SQL and many MCP tools
clio add-custom-logging ...                   # NLog routing for one package
```

`run` executes a YAML scenario of commands with shared settings - the way to replay a
deployment or a test sequence without a shell script. `listen` streams the site's log.

For the C# test content itself use the code recipes (`search_recipes("unit test", area=
"Backend")`), not this block.

## Unit tests without an instance (verified 2026-11-08, clio 8.1.0.147, workspace on 8.2.3)

```bash
clio new-test-project --package UsrPkg          # from the workspace root; needs packages/UsrPkg/Files/UsrPkg.csproj
dotnet test tests/UsrPkg/UsrPkg.Tests.csproj -c dev-nf    # net472; -c dev-n8 for .NET 8
```

The scaffold is `tests/<Pkg>/<Pkg>.Tests.csproj` + `BaseComposableAppTestFixture.cs` +
`Libs/` (Creatio's own kit: `UnitTest.dll` with `BaseConfigurationTestFixture`, `SelectData`;
`Terrasoft.TestFramework.dll`; `ATF.Repository.Mock.dll`). NUnit 4, FluentAssertions 7,
NSubstitute come from NuGet. Tests derive from `BaseComposableAppTestFixture` and get a fake
`UserConnection`; recipe `Backend/C#/Tests/HowToUnitTestAnEntityEventListenerWithoutAnInstance`
shows the schema mocks, the data mock and the two attributes the fixture needs.

Traps met on the way, all reproducible:

- **`Libs/UnitTest.dll` is built against Terrasoft.Core 8.3.2.4166.** A workspace on an older
  core fails with CS1705 at compile time. Fix: [unit-tests/Directory.Build.props](unit-tests/Directory.Build.props)
  in `tests/` points `TestCoreLibPath` at a local 8.3.2+ installation's `Terrasoft.WebApp/bin`
  (the package projects keep the workspace core), and [unit-tests/App.config](unit-tests/App.config)
  next to the test csproj redirects every Terrasoft.* assembly at run time - without it SetUp
  dies with `FileLoadException`; the SDK's automatic redirects do not cover these.
- **A user task made as files has no platform half** (`Autogenerated/Src/<Task>Schema.<Pkg>.cs`),
  so the package project fails with CS0115 "no suitable method found to override". The
  `tools/usertask` toolkit writes that file on save for any package with a `Files/*.csproj`.
- **`[EntityManagerSettings(EntityManagerMode.ReinitByCustomSchemas)]` and `[MockSettings(RequireMock.All)]`**
  on the fixture class, or `MockEntitySchemaWithColumns` throws a NullReferenceException (the
  default entity schema manager is not the test one the helper casts to).
- The kit is faithful about **not-loaded columns**: `GetTypedColumnValue` on a column the test
  did not set throws `InvalidObjectStateException`, exactly as the platform does on a partial
  insert - guard with `IsColumnValueLoaded`. The listener in the test package had that bug.

Reachable without an instance: entity values and the listener's branching, ESQ reads (served by
`SetUpTestData`), localizable strings (`MockLczValues`), web services with a mocked HttpContext.
Not reachable: `Entity.Save`, `Insert`/`Update`/`Select` against the DB, `DcmSchemaManager`,
`EnsureDBConnection`, processes - prove those over OData from outside.

Verified on 8.2.3: MCP `trigger-smoke {entity, values, watch, cleanup}` creates the record,
waits 15 s for a process run and cleans up; without a signal-started process on the entity
it reports "no run started" - that is the expected answer, not a failure. MCP
`add-item-model {namespace, folder}` generated 920 entity model classes in 14 s.
`assert-infrastructure` / `show-passing-infrastructure` / `find-empty-iis-port` run locally
and report what the host has (no Kubernetes, one PostgreSQL, no Redis here).
